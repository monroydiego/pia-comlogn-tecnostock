# ADR-009. Persistencia con EF Core y SQL Server, y Unidad de Trabajo transaccional

**Estado:** Aceptada (nueva en el PIA)

## Contexto
U3 usaba repositorios en memoria. El PIA exige base de datos, Docker Compose y despliegue. El equipo eligió .NET 10, C# y SQL Server. Las invariantes de ADR-002 (serie única, un apartado vigente por unidad) y ADR-003 (una transacción por caso de uso) deben sostenerse con una base de datos real.

## Alternativas
Mantener la memoria; Dapper con SQL escrito a mano; EF Core con SQL Server.

## Decisión
EF Core con SQL Server, solo en infraestructura. Los repositorios implementan las interfaces del dominio, y UnidadDeTrabajoEfCore abre la transacción, la confirma o la descarta y publica los eventos tras confirmar. Índice único sobre la serie, token de concurrencia en la versión de cada aggregate y datos semilla para el catálogo.

## Consecuencias
Beneficio: persistencia real sin que el dominio dependa de EF Core ni de SQL; las pruebas de dominio siguen sin base de datos. Costo: configuración de mapeos y de concurrencia, y SQL Server consume más memoria en Docker y en el despliegue.

## Trazabilidad
RN-INV-002, RN-APT-003; BR-003, BR-004; US06, US17; requisitos del PIA (persistencia, Docker Compose).
