# ADR-001. Domain Model como patrón de lógica de negocio

**Estado:** Aceptada

## Contexto
Reglas cruzadas entre apartado, unidad, venta y devolución; estados con transiciones; parámetros aún supuestos; problema de venta accidental de apartados y de series sin trazabilidad.

## Alternativas
Transaction Script (reglas duplicadas, estados dispersos); Table Module (reglas entre tablas sin dueño); Domain Model.

## Decisión
Domain Model para los comandos (CU-01 a CU-05) y Transaction Script solo para lecturas. Table Module descartado.

## Consecuencias
Beneficio: invariantes en un solo lugar y pruebas sin infraestructura. Costo: más clases, mapeo de persistencia y disciplina para no mover reglas a los servicios. Trabajo posterior: validar los supuestos con el stakeholder.

## Trazabilidad
BR-003, BR-004, BR-005; RN-APT-002/003, RN-INV-003, RN-DEV, RN-SUP; US06, US07, US13; H-01 a H-08.
